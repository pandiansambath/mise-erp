## 0 · SERIOUS — purchasing basket (staff are blocked)

> "we got a serious bug we need to solve this on priority — staff are getting
> affected... you can notice that basket is missing in 2nd pic. if i move cursor
> that basket is flickering and hidden. somehow i tried and clicked basket, now
> when i click submit indent nothing is happening. please use playwright to test
> the functionality. this is real bug."

Two separate faults, both mine, both found in the code before touching the site.

- [x] **0.1 "Submit indent" does nothing.**
      `SheetPopup` renders through `createPortal(ui, document.body)`. A portal
      keeps the REACT tree but not the DOM tree, and `<button type="submit">`
      submits the form it is a DOM descendant of. The button is passed down
      `<form>` → `OrderFlow footer` → `BasketSheet footer` → portal, so in the
      DOM it is a child of `<body>` with no form owner at all. Clicking it is a
      no-op — exactly what he saw. Fixed with the HTML form-owner attribute
      (`<form id>` + `form="…"` on the button), which works across ancestry.
      *Broke when I extracted SheetPopup to a portal; nothing was checking it.*
- [x] **0.2 Basket disappears / flickers.**
      The drag clamps against `window.innerWidth`, which INCLUDES the vertical
      scrollbar, so the basket can be parked in the strip under it. A `fixed`
      element there overflows the page — which is the horizontal scrollbar that
      appears in his 2nd and 3rd screenshots and not the 1st. The remembered
      position was also never re-checked: it is read from localStorage and
      applied whatever the window is now. Clamp on the client width, re-clamp on
      load and on resize.
- [x] **0.3 Playwright proof** of add → basket → submit → indent created.

### Proven BEFORE fixing, against the live site (2026-09-05)

Both faults reproduced on prod before a line was changed, which is the only way
to know a fix is a fix rather than a coincidence:

```
submit indent   button found, clicked, waitForRequest(POST /purchasing/indents)
                TIMED OUT after 20s — no request was ever made
basket position planted {x:6000,y:4000}; measured x+width = 6423.58
                on a 1280 viewport
```

The first version of the submit test keyed on a `data-testid` that this same
commit adds, so it could only ever report "element not found" — it could not
tell the bug from the fix not being deployed. Matching the visible words instead
is what produced the evidence above.
